## 当前默认调试配置

`Hardware/hal_uart.h`：

```c
#define APP_DEBUG_UART_ENABLE  1
#define APP_LOG_ENABLE         1
#define APP_LOG_CHARGE         0
#define APP_LOG_WIFI           1
#define APP_LOG_POWER          1
#define APP_LOG_TIME           0
```

`APP_CHARGE_DEBUG` 保持为 `APP_DEBUG_UART_ENABLE` 的兼容别名，继续用于已有 GPIO、UART、UV、STOP 引脚判断和充电驱动分支。只把应用日志的保护条件迁移到对应 `APP_LOG_*_ON`，没有全局替换硬件宏，也没有将应用总开关加入 putchar 去控制 SDK 日志。

日志关闭时，充电函数仍被定义为空函数，避免调用仍存在而函数被排除造成 L127/L128。充电驱动中原有维护及快照路径继续保留。原缺水调试旁路、固定温度和充电参数未随日志整理变动。

## 板级日志已确认与待定位项

用户确认不联网也能进入整机低功耗。最后一轮时间戳为：

| 记录 | 时间/间隔 |
| --- | --- |
| BOOT 5 | 16:34:48.133 |
| BOOT 180 | 16:37:40.897；从 BOOT 5 起经过 172.764 秒 |
| 首次采样到 Wi-Fi SLEEP / STOP 准入通过 | 16:37:45.837，p=2、lp=2、q=0000、ok=1 |
| 中间通信阶段 | 16:38:45.084，p=4；约一分钟后发生 |
| 再次采样到 Wi-Fi SLEEP | 16:38:50.023 |
| 用户确认入睡前最后日志 | 16:39:54.192；不把此时间当作精确的硬件 STOP 时刻 |

BOOT 软件计时未显示变慢。超过三分钟的主要额外时间位于 BOOT 结束之后。源码主机复现表明：若离线 BOOT 未成功上报过温度，离开 BOOT 后首个 60 秒温度检查可触发一次唤醒，发送完成后再等待五秒释放；这一过程与日志节奏吻合，但未用板上逐事件记录确认就是该次唤醒来源。

MCU 仍要求 `s_power_idle_10ms` 累计到 6000；外部输入锁存和睡眠流程退出均可能清零。10ms 标志是待处理标志而非累计 tick，主循环阻塞会使这段空闲时间偏长。具体清零来源与延时占比仍待诊断，本基准没有修改这些准入和计时规则。
